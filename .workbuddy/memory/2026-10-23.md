## GitHub Pages 部署打通

用户贴的报错是 `actions/configure-pages` 拿不到 Pages 站点：

```
Error: Get Pages site failed. Please verify that the repository has Pages enabled and configured to build using GitHub Actions
Error: Not Found - https://docs.github.com/rest/pages/pages#get-a-apiname-pages-site
```

本地仓库原本**没有** `.github/`（远端 ref 上也没有），说明失败的那次是 GitHub web UI 生成的
Pages 起手模板，或是在启动器仓库里跑的。

### 改动

- 新增 `.github/workflows/deploy.yml`：`npm ci` → `npm run generate` →
  `actions/configure-pages@v5`（带 `enablement: true`）→ `upload-pages-artifact@v3`（`path: .output/public`）
  → `deploy-pages@v4`；权限 `contents: read / pages: write / id-token: write`，
  `concurrency.group: pages` 且 `cancel-in-progress: false`。
- `nuxt.config.ts`：`app.baseURL = process.env.NUXT_APP_BASE_URL || '/'`，
  `nitro.prerender.routes: [baseURL]`（原来写死 `'/'`，带 baseURL 时会只生成一条 `/` → baseURL 的跳转页，
  产物里只剩一个 16 字节的 `index` 文件、没有 `index.html`）。favicon 的 href 走 `withBase()`。
- 新增 `composables/useAsset.ts`：`public/` 资源必须拼 baseURL，否则子路径部署下 404；
  `AppShot.vue` 改用 `useAsset()`（原来硬写 `/screens/launch.png`）。
- README 补「部署到 GitHub Pages」一节；`.gitignore` 加 `.vs`。

### 踩坑

- **Git Bash 会改写 `/vbl-website/` 这种环境变量值**，把它当成路径转成 `D:\Program Files\...\vbl-website`，
  导致构建报 `ENOENT: mkdir '.output\public\D:\...'`。本地验证必须
  `MSYS_NO_PATHCONV=1 NUXT_APP_BASE_URL=/vbl-website/ npm run generate`。CI 是 Linux，不受影响。
- 构建日志里偶发 `ERROR EPERM: open '.output\public\index.html'`（杀软/占用），但 exit=0 且产物完整。
- 本机到 github.com `git fetch` 返回 `Empty reply from server`，推不上去，commit 已留在本地
  （`4fd03f2`），等用户自己 push。

### 验证

- `NUXT_APP_BASE_URL=/vbl-website/` 构建后确认 `index.html` 在产物根目录，
  引用全部是 `/vbl-website/_nuxt/*`、`/vbl-website/screens/launch.png`、`/vbl-website/favicon.svg`。
- 默认构建（无该 env）仍是 `/_nuxt/*`，预览 `http://127.0.0.1:4411`。

## CI 报 Cannot find module @rollup/rollup-linux-x64-gnu

第二次跑 CI 的报错：`Loading @nuxt/nitro-server server builder failed` →
`Cannot find module @rollup/rollup-linux-x64-gnu`。

根因：`package-lock.json` 是 Windows 上生成的，npm 把「非本平台」的 optional 原生绑定裁掉了
（npm/cli#4828）。实测旧锁里 `@oxc-*` / `@rolldown/*` 各平台齐全，但
`@rollup/rollup-*` 只有 win32 两个、`lightningcss-*` 只有 win32 一个 → Linux 上必炸。

处理：

- workflow 加 `Add missing linux native bindings` 步骤：按 `node_modules/rollup/package.json`
  的版本号 `npm i --no-save @rollup/rollup-linux-x64-gnu@<v>`（lightningcss 存在则一并补），
  装完 `require()` 一次做校验。
- 想彻底解决需在 Linux 上 `rm -rf node_modules package-lock.json && npm install` 后提交锁文件。

**顺带发现的严重问题**：CI runner 路径是
`/home/runner/work/vibrantbitlauncher-website/vibrantbitlauncher-website`，
说明 GitHub 仓库已改名 `vibrantbitlauncher-website`（本地 remote 还是旧的 `vbl-website`）。
之前写死的 `NUXT_APP_BASE_URL=/vbl-website/` 会让线上资源全 404，已改成
`/${{ github.event.repository.name }}/`，以后改名不用再动 workflow。

### 环境坑（新增）

- **本机到 npm registry 也不通**：`npm install --package-lock-only` 挂 2 分钟无输出，
  只能 `Stop-Process` 掉（`Get-CimInstance Win32_Process -Filter "Name='node.exe'"` 里筛
  `*npm-cli.js*install*`）。所以锁文件只能等用户在网络正常时重建，或靠 CI 补包。
- 删锁重装的两个备份（`E:\lock.bak.json` / `nm-backup`）已清理，`package-lock.json` 与原来一致。
