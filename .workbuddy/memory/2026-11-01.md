## GitHub Actions：跨仓库 CHANGELOG.md 触发部署

**背景**：站点仓库 `EasyColorful666/vibrantbitlauncher-website`（默认分支 master，Pages 已启用）
的更新日志数据来自启动器仓库 `EasyColorful666/VibrantbitLauncher.Avalonia` 的
`CHANGELOG.md`（默认分支 master，public）。需求：那边 CHANGELOG 更新后自动触发本站部署。

**关键约束**：GitHub Actions 原生不支持监听另一个仓库的 push（`workflow_run` 也只在同仓库内
有效）。只能用两条路叠加：

1. `repository_dispatch`（即时）—— 需要对方仓库配 PAT 调 dispatches API
2. `schedule`（兜底）—— 每天 UTC 02:17 轮询，内容真的变了才构建

**实施**（`.github/workflows/deploy.yml` 重写）：

- 触发：`push[master,main]` + `repository_dispatch[changelog-updated]` + `schedule` + `workflow_dispatch`
- 拆出 `changelog` job 做变更探测（仅 schedule/dispatch 触发时运行，push 时 `if` 跳过）
- 探测用 contents API（`Accept: application/vnd.github.raw`）而不是 raw.githubusercontent.com
  —— raw 走 CDN 有缓存，刚推完几分钟内可能拿到旧内容导致误判「无变化」
- 变更比较只比 `count` + `releases`，必须剔除 `generatedAt`（时间戳）和 `source`（临时路径），
  否则每次都判定为变化，跳过逻辑失效
- `build` job 条件：`needs.changelog.result == 'skipped' || needs.changelog.outputs.changed == 'true'`
- build 内新增 Sync CHANGELOG 步骤：下载到 `$RUNNER_TEMP/CHANGELOG.md` →
  `CHANGELOG_PATH=... node scripts/build-changelog.mjs`，再 `npm run generate`

**踩坑记录 / 待办**：

- `scripts/build-changelog.mjs` 的 `existsSync(SOURCE)` 对 http URL 恒为 false，
  默认 URL 分支永远走「找不到，保留现有 json」直接 exit 0。CI 里靠下载到本地 + CHANGELOG_PATH 绕过。
  本地 `npm run changelog` 实际什么都不做。
- `assets/data/site.ts` 里 CHANGELOG 外链写的是 `blob/main/CHANGELOG.md`，上游默认分支是 master，该链接 404。

## 后续：两个 bug 已修

**1. `scripts/build-changelog.mjs` 支持远程 URL**
- 新增 `readSource()`：`/^https?:\/\//i` 判定远程 → 全局 `fetch`（Node 18+）拉取；
  否则按本地路径 `existsSync` + `readFileSync`。
- 错误语义按场景区分：
  - 远程拉取失败（4xx/5xx/网络）→ **exit 1**，CI 里必须能看见，不能静默用旧数据发布；
  - 本地路径不存在 → **exit 0**，保留现有 json（没 clone 启动器仓库的机器也能跑）。
- 默认 URL 从 `refs/heads/master/` 简化为 `master/`（标准形式）。
- 顶层 `await` 可用（.mjs）。
- 验证方式：本地起 http server 模拟 200 / 404，两条分支分别 exit 0（写出 2 个版本）和 exit 1。
  本机直连 github raw 不通（curl exit 35 / node fetch failed），故用本地 server 验证。

**2. `assets/data/site.ts` 两处外链分支修正**
- 第 231、419 行 `blob/main/CHANGELOG.md` → `blob/master/CHANGELOG.md`（上游默认分支是 master）。

workflow 里仍保留 curl（带 `--retry 3`、失败显式报错）而不是改用脚本 URL 模式，是为了重试能力。
